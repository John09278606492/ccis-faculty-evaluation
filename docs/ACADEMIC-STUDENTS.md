# Academic students and evaluation sections

1. Open Academic Management > Students. Staff need `view_academic_students`, `manage_academic_students` and `import_academic_students` for uploads; assigned campus and department limits still apply.
2. Upload the original campus **student-list report** directly, including its title rows and repeated Subject Code / Description / Lec / Lab / Units columns. The report detects its campus and academic period, degree program and subject enrolments. See [campus master list workflow](CAMPUS-MASTER-LIST.md). The example CSV remains supported with columns: student_id, first_name, middle_name (optional), last_name, email (optional), department_code, sections (optional). A separate editable year level is not used; include it in section names (e.g. BSIT 3A). Use a pipe to separate multiple sections in the CSV, e.g. BSIT 3A|BSIT 2B. Section names are normalized to uppercase. Students may belong to multiple sections. Repeated imported IDs merge section memberships without duplicating accounts; manual editing can remove memberships.
3. Uploads support mixed sections/departments within the operator's assignments. Imports are atomic: errors show a row number and roll back every row. Accessible existing student IDs update profiles without changing passwords or removing roles; other accounts are protected. No existing student is automatically moved based on their old roster.
4. Valid missing subjects are automatically added to **Courses** during the reviewed import when the importer has course-creation permission. Existing codes are reused within the department; conflicting titles/units are listed for review. **Sync Courses from Enrolments** handles already-uploaded subject data without re-uploading students. Open Teaching Classes, select the actual course, instructor and section, then use **Evaluators > Add from Master List Subjects** to identify the eligible students. Choose programs and optional reported-year filters, then confirm who attends this section. **Add Sections / Custom Students** remains available for explicit section groups, additional students, and exclusions. Existing individual attach/detach and ID-list import remain available.
5. Assignment selection is a snapshot: later profile changes or new students do not silently change the evaluator list. Reapply the selection when needed. Existing submitted responses are preserved when a student is removed from the roster.

Academic profiles are stored on existing student accounts, not separate duplicate accounts. An omitted email receives an internal placeholder on account creation; evaluation entry uses the student ID. Assessment PIN access remains separately managed. Annex B supervisor assignments do not use section selection.

Student managers with `delete_academic_students` can use **Delete** on a student row, on the edit page, or for selected rows. Confirmation explains that this removes the active account and disables sign-in while retaining submitted responses, legacy ratings, comments, original instruments, printable copies, academic records and historical report counts. Evaluator identity remains hidden unless the viewer has the existing identity permission. Student IDs remain reserved; uploads cannot recreate or reactivate deleted accounts.

Deletion also requires `view_academic_students` and `manage_academic_students`, membership in the selected campus and authority over the student's home department. Seeing a visiting student through a class roster does not authorize deleting their account. Only a super administrator may delete a student account shared across multiple campuses. Staff/student hybrids and privileged student profiles are protected. Bulk operations validate the entire selection first and record an audit event per student. Existing roles with both student-management and user-deletion permissions receive the new permission during migration; other roles can be granted it explicitly through Roles.

Existing single-section values are migrated to the multiple-sections field. Old year-level values are retained for historical compatibility but no longer drive grouping or appear in this academic workflow. Selecting overlapping sections includes each student only once.
